# Локальная копия реферальной программы

Статус: локальная версия реализована и проверена. Используются настоящие пакеты Reactor из внутреннего реестра, указанного пользователем.

## Задача

Воссоздать существующий интерфейс страницы `#/ReferralProgram` на локальном компьютере, чтобы затем менять и проверять интерфейс. На первом этапе сохраняем содержание, визуальную иерархию и поведение, показанные в Figma. Переработку UX пользователь пока не заказывал.

Источники:

- [Figma, «Итоговый макет»](https://www.figma.com/design/423yOuw412te1aSw1s69jl/?node-id=20820-67232).
- [Тестовая среда](https://www.qatl.ru/app/loyalty/extranet/#/ReferralProgram). Доступ подтверждён через встроенный браузер после входа пользователя. Просмотрены основная страница и нижние блоки наград. Изменения на стенде не сохранялись. Chrome через нативный Computer Use ранее был недоступен из-за невозможности достоверно определить URL; для продолжения используем встроенный браузер.
- [LK_B2B](https://github.com/Polina-ko-dis/LK_B2B), скачанная копия `reference-lk-b2b`, исходный HEAD `e975a6090bdc4b2c8967d26fec5e0dd7ac2a8abd`.

## Выбранный подход и альтернативы

Подход следует из запроса пользователя: локальное React-приложение на настоящих `@reactor/*`, меню адаптируется из LK_B2B. В исходном проекте используются Vite, React, ReactorTheme и CSS с токенами Reactor. Сохраняем этот способ подключения; конкретные версии согласуем с доступными пакетами.

Полное подключение к Extranet потребовало бы серверных контрактов и авторизации, которые не нужны для локальной проверки UI. Воспроизведение элементов на обычном HTML вместо Reactor противоречит требованию пользователя. Эти альтернативы в реализацию не входят.

## Состав первой версии

- Оболочка Extranet: левая панель шириной 288 px на основном десктопном размере, верхняя панель с сохранением, подвал. Меню и шапку берём из LK_B2B; активный пункт — «Реферальная программа» внутри управления гостями.
- Заголовок «Реферальная программа».
- Начальное состояние берём с открытого стенда: вариант со скидками, флажки наград выключены, селекты категорий и ограничение регистраций неактивны. В селектах стенда используется текст «не выбрано»; в Figma — «Выбрать». При реализации ориентируемся на Figma как визуальный эталон, отличие фиксируем для последующей сверки.
- Вводная карточка «Привлекайте новых лояльных гостей через реферальную программу» и инструкция, как в Figma.
- Карточка «Вознаграждения для постоянных гостей»: за регистрацию приглашённого гостя и за его первое проживание.
- Карточка «Вознаграждения для приглашённых гостей»: за регистрацию, информационное сообщение и дополнительные награды.
- Награды: ваучер категории; баллы в соответствующем варианте программы; повышение уровня лояльности за первое проживание, где оно предусмотрено макетом.
- Ограничение наград за первые N регистраций, связанные поля и подсказки.
- Сохранение, состояния «деактивирована»/«активирована», диалог активации, уведомление о сохранении, предупреждение о несохранённых изменениях.

Карточка гостя и история операций видны в общей секции Figma, но относятся к другим страницам. В первую версию страницы ReferralProgram их не включаем — это предварительное ограничение объёма, принятое исполнителем по адресу тестовой страницы.

## Состояния и локальные данные

Выбор исполнителя: добавить компактную панель прототипа по образцу DevPanel из LK_B2B, чтобы переключать варианты «Скидки»/«Баллы» и демонстрационные состояния без изменения серверных данных. Панель должна быть явно отделена от копируемого интерфейса и убираться для сверки макета.

Форма использует локальные демонстрационные категории ваучеров и данные программы. Выбранный флажок включает соответствующие зависимые поля. Изменения хранятся отдельно от сохранённой конфигурации; сохранение выполняется только после проверки активных полей. Сохранённые настройки сохраняются в localStorage с собственным префиксом проекта. Действия активации и деактивации меняют только локальное состояние.

Точные ограничения числовых полей и тексты ошибок берём из соответствующих макетов валидации. Неизвестные бизнес-правила не выдаём за поведение работающего сервиса.

## Компоненты и структура

Использовать ReactorTheme, PageTop, Tile, Text, Label, Checkbox, Select, Field/подходящий числовой компонент, Button, Icon, InfoAlert и компоненты окон/уведомлений Reactor. Перед реализацией каждого элемента проверить API через MCP и исходники установленной версии. Иконки — штатные Reactor при точном соответствии макету. Раскладки страницы и меню допускают CSS с переменными Reactor, как в исходном LK_B2B.

Предлагаемые модули: оболочка и Navigation; ReferralProgramPage; общая группа наград; отдельные блоки наград постоянным и приглашённым гостям; локальное состояние и демонстрационные данные. Экран не должен быть одним монолитным компонентом — следующие правки должны затрагивать отдельный блок.

## Визуальные ориентиры

Основной эталон — Figma при ширине 1600 px: боковая панель 288 px, рабочая область с отступами 32 px, расстояния между карточками 24 px, колонка подписей 216 px и зазор до полей 24 px. Цвета, поля, типографику и окна задаёт Reactor. Точные параметры берутся из детальных ответов Figma и сверяются в браузере.

Изучены детальные контексты карточек: вводная `26053:132034`; скидки `25772:15649`, `25772:15702`; баллы `25772:19584`, `25772:19637`; заполненные баллы `25772:21028`, `25772:21105`; статусы `25772:17539`, `25772:19526`; диалог активации `21756:76880`. Целые экраны возвращают сокращённую структуру, поэтому не используются как единственный источник реализации.

## Проверка результата

Установить реальные зависимости; успешно собрать проект; запустить локальный сервер только на 127.0.0.1. Открыть страницу в доступном браузере, сверить основной десктопный вид и состояния со скриншотами Figma. Проверить переключение наград, зависимые поля, сохранение, перезагрузку и локальную активацию. Добавить содержательные проверки модели формы для зависимостей и сохранения. Подготовить короткие инструкции запуска.
